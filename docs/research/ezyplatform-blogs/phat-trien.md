# Phát triển plugin, theme và nội dung

[Về chỉ mục blog](README.md) · [Guide kỹ thuật](../ezyplatform-guide-inventory.md#phát-triển-và-đóng-gói) · [Skill xây dựng plugin của stack](../../../skills/ezy-build-plugin/SKILL.md)

## Dự án Java và module

- [Tạo dự án theme/plugin](https://ezyplatform.com/blog/tao-du-an-ezyplatform-theme-va-plugin?lang=vi): cài runtime và SDK, thêm `EZYPLATFORM_SDK/bin` vào PATH, dùng Maven để build thư viện của `ezyplatform-development`. Ví dụ SDK cũ: `ezy.sh cp hello-world -g com.example -i admin-plugin,theme,web-plugin`. Import Maven project, đặt working directory về đúng module, chạy startup test, rồi export và kích hoạt trên runtime kiểm thử. Bài dùng `bash export.sh` và kiểm tra ZIP dưới `target/project/`; dùng skill hiện hành để chọn lệnh scaffold/export của stack.
- [Cấu trúc dự án](https://ezyplatform.com/blog/cau-truc-du-an-theme-plugin-ezyplatform?lang=vi): SDK dùng chung cho các model/entity/repository/service; Admin plugin phục vụ quản trị, Web plugin phục vụ API, theme phục vụ giao diện; Socket plugin và Socket app dành cho tác vụ/kết nối realtime. Một dự án có thể chỉ chứa các module cần thiết. Không xem theme là nơi thay thế quyền truy cập hay logic nghiệp vụ của plugin.
- [Menu Admin](https://ezyplatform.com/blog/huong-dan-lap-trinh-menu-cho-ezyplatform-admin-plugin?lang=vi): dùng `menus.properties` theo module; xem [Guide menu](https://youngmonkeys.org/ezyplatform/guides/create-menus-for-admin-plugin?lang=vi) để đối chiếu vị trí, nhãn đa ngôn ngữ và link. Kiểm tra route và quyền API sau export; sự hiện diện của mục menu không chứng minh người dùng được quyền sửa dữ liệu.
- [Bảng plugin](https://ezyplatform.com/blog/tao-bang-trong-ezyplatform-plugin?lang=vi) đặt SQL trong thư mục resources `scripts` của module **Admin**; Web/Socket không quét script đó. Dùng tiền tố tên plugin cho bảng, `CREATE TABLE IF NOT EXISTS` khi tạo mới, rồi viết entity, repository và integration test. Kiểm chứng SQL trên DB dev và phân biệt cập nhật schema với chạy lại migration.
- [Sự kiện nội bộ](https://ezyplatform.com/blog/tao-va-xu-ly-su-kien-noi-bo-internal-event-trong-ezyplatform-plugin?lang=vi) tách lớp event, bộ quản lý và handler; handler ở plugin khác có thể nhận trong cùng runtime. Event không truyền từ Admin sang Web/Socket hay sang máy chủ khác; đây không phải hàng đợi bền vững. [Data appender](https://ezyplatform.com/blog/tao-batch-data-appender-trong-ezyplatform-plugin?lang=vi) là hướng khác cho xử lý nền theo lô.

## Low-code, trang, fragment và API

- [Page fragments cho theme](https://ezyplatform.com/blog/su-dung-page-fragments-cac-phan-trang-cho-ezyplatform-theme?lang=vi) và [chuẩn bị low-code](https://ezyplatform.com/blog/ezyplatform-low-code-chuan-bi-moi-truong?lang=vi): trước khi sửa theme Java, xác định nội dung có thể quản lý từ Admin, trang/fragment được theme ghép ở đâu và phần nào cần viết module. Trong site dùng EzyArticle, đồng bộ project trước khi sửa; dùng skill ezy-author/media/i18n/verify và chỉ publish sau phê duyệt.
- [Đưa dữ liệu thật vào Ezyvora](https://ezyplatform.com/blog/huong-dan-dua-du-lieu-that-tu-ezyplatform-vao-website-ezyvora?lang=vi): liệt kê mock data rồi ánh xạ thuộc tính sang nội dung cấu hình hoặc bài viết được quản trị. Đưa từng vùng nhỏ vào trước, giữ nguyên giao diện trong lúc thay nguồn dữ liệu. Với nội dung cần SEO, ưu tiên HTML do server render; API phía client phù hợp với vùng tương tác không phụ thuộc SEO. Kiểm tra từ thay đổi trên Admin đến Web, kể cả bài chưa xuất bản, dữ liệu rỗng, lỗi và ảnh thiếu; sau đó dọn mock còn sót.
- [Ghép API EzySupport](https://ezyplatform.com/blog/huong-dan-ghep-api-ezysupport-vao-website-doanh-nghiep-ezyvora?lang=vi): đối chiếu các trường của form với API hiện có, không đặt token Admin ở frontend, và kiểm tra cả thông báo trên Web lẫn yêu cầu tương ứng trong Admin → EzySupport. [Page Fragment Blog](https://ezyplatform.com/blog/huong-dan-cai-dat-page-fragment-blog-cho-website-doanh-nghiep-ezyvora?lang=vi): kiểm kê fragment trước, tái sử dụng phần danh sách/chi tiết nếu có, ghép lại vào trang và thử từ màn danh sách đến từng bài. Đây là các bước của bộ Ezyvora, không phải danh sách endpoint được bảo đảm trên mọi instance. Kiểm tra plugin/theme thực tế và xem `ezy-guide` trước khi gọi API.
