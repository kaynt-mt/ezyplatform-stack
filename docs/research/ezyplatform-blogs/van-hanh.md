# Operations, architecture, and updates

[Back to the Blog index](README.md) · [Operating system and infrastructure guides](../ezyplatform-guide-inventory.md#installation-and-operations)

## Separate runtimes, modules, and applications

- [Software architecture](https://ezyplatform.com/blog/kien-truc-phan-mem-cua-ezyplatform?lang=vi): The core provides shared services such as users and administrators, permissions, media, scheduling, and module management. Plugins add capabilities such as content, e-commerce, or email; the theme is the presentation layer. Do not modify the core just to change a page or a business process.
- [Single-server deployment](https://ezyplatform.com/blog/mo-hinh-trien-khai-ezyplatform-tren-mot-may-chu?lang=vi): Admin (9090), Web (8080), and Socket can run separately. Do not enable Socket simply because EzyPlatform is installed. The article lists default Socket ports TCP 3005, UDP 2611, WS 2208, and WSS 2812. Verify the actual configuration instead of using this list as a firewall policy.
- [Settings management](https://ezyplatform.com/blog/ezyplatform-quan-ly-cai-dat-the-nao?lang=vi): `ezy_settings` uses a unique, snake_case `setting_name`, a type, a value, and an update timestamp for caching. Use typed methods in `SettingService` such as `getLongValue` and `setLongValue`. Prefer Admin for changes; do not automatically enable writes from Web or Socket. Application settings are separate from bootstrap datasource configuration.

## Install, deploy, and operate Admin

- [Manual local installation](https://ezyplatform.com/blog/cai-dat-ezyplatform-tren-may-local?lang=vi): Prepare the JDK and MySQL, edit the datasource in `settings/setup.properties`, set `JAVA_HOME` and `EZYPLATFORM_HOME`, and check `java -version`. The article runs `bash cli.sh "console admin"` to open `/setup-admin`, then stops the console before running `bash cli.sh "start admin"`. Web and Socket have Start buttons on their respective runtime dashboards. These commands use the distribution CLI, not the repository's `./scripts/ezy` wrapper.
- [Ubuntu server](https://ezyplatform.com/blog/trien-khai-ezyplatform-len-ubuntu-server?lang=vi): Choose a server, set up SSH, the firewall, the timezone, MySQL, and a database user, and use Nginx and Certbot. Verify Admin and Web first; set up Socket TLS only when using Socket. The article uses JDK 8 and includes a Java 17+ note; [this stack](../../../README.md) uses Java 11 and Docker Compose. Follow the repository for the development stack and do not copy sample firewall, datasource, or reverse proxy settings straight into production.
- [Install a theme or plugin](https://ezyplatform.com/blog/huong-dan-cai-dat-theme-plugin-cho-ezyplatform?lang=vi): In Admin, go to Components → Themes → Add New, find the theme, purchase it if necessary, and select Add. Install missing dependencies, use Activate & Restart, and verify the Web URL. **Deactivate** means the theme is active; **Activate** means it is inactive. Plugins may follow a different process; check the restart requirements of the runtime in use.
- [Upgrade a theme or plugin](https://ezyplatform.com/blog/ezyplatform-quan-ly-cac-phien-ban-plugin-va-theme-the-nao?lang=vi): Download and Apply are separate steps. The ZIP is unpacked in the upload area; Apply runs the restart and copy process for the affected runtime. Check core version and dependency requirements first (for example, ELearning depends on Ecommerce). Use the stack's pinned versions and backup and restore plan. Do not upgrade production just because an Update button is visible.

## Distinguish updates from news

An explanation of how updates work is not a release note. Articles about projects, partners, or roadmaps do not establish that the running version includes a feature. Before relying on a feature, check the core version in the [stack README](../../../README.md), plugin requirements in the [runtime plugin catalog](../../plugins/README.md), the upstream version, and the release documentation.
