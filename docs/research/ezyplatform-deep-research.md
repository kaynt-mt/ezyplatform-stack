# EzyPlatform 1.5.9 research for plugin development

**Goal:** Identify what plugins can reuse from EzyPlatform, what they must own, and what assumptions to verify on the runtime. This is research based on public documentation and source code, not a test report. See the [guide inventory](ezyplatform-guide-inventory.md) and [framework research](youngmonkeys/index.md).

## Conclusions

1. **EzyPlatform is an extensible runtime**, not just a CMS, and its source code is not fully open. Put new applications in separate repositories and build on the existing core rather than forking it to add business features. [Introduction](https://ezyplatform.com/ezyplatform-introduction) · [FAQ](https://ezyplatform.com/faq) · [Stack README](../../README.md).
2. **Use Admin for operations and Web for application users.** The core authenticates identities; the plugin authorizes access to business data.
3. **Own the schema and API contract.** Reuse HTTP, media, localization, notifications or internal messages, and pagination patterns where appropriate. Do not force business data into CMS tables.
4. **Add Socket only for real-time needs.** Keep an authoritative read path and check authorization both at subscription and before delivery.

## Runtime, modules and tools

| Component | What the documentation says | Plugin guidance |
| --- | --- | --- |
| Admin (default 9090) | Multiple Admin plugins can run at once, extending menus, views, and APIs. | Use Admin for integration configuration, job status, and support, not as a substitute for the business UI. |
| Web (default 8080) | Multiple Web plugins can provide APIs or extend the UI, but only one theme is active at a time. | Package the Web API first and check how to mount the app in the active theme without changing the entire site. Consider a separate theme for a dedicated instance. |
| Socket | EzyFox Server supports TCP, UDP, and WebSocket. A Socket plugin typically handles login and background tasks; Socket apps handle real-time requests. Admin and user tokens are different. | Leave the port closed if the MVP does not need it. Prefer WSS when adding it and do not rely on subscriptions as the only data source. |
| Data and UI | EzyData, Hibernate, JPA, and HikariCP; EzyHTTP and Jetty; Thymeleaf templates and Bootstrap/jQuery sample interfaces. | Follow EzyHTTP and EzyData conventions rather than assuming Spring Boot. Choose a plugin UI independent of the theme lifecycle after investigating integration. |
| Project SDK | The `book-store` and `personal` examples use a shared `*-sdk` and deployable modules; no separate `*-common` module is required. | Keep shared entities, repositories, services, policies, and DTOs in `<project>-sdk`. Separate controllers, interceptors, and assets by runtime. |

The source: [the structure](https://youngmonkeys.org/ezyplatform/guides/ezyplatform-structure?lang=vi), [tech stack](https://youngmonkeys.org/ezyplatform/guides/ezyplatform-tech-stack?lang=vi), [theme and Plugin](https://youngmonkeys.org/ezyplatform/guides/understanding-ezyplatform-themes-and-plugins?lang=vi), [structure of the project](https://youngmonkeys.org/ezyplatform/guides/the-structure-of-a-plugin-project?lang=vi).

- `module.properties` describes a deployable module, `menus.properties` is for Admin, and `assembly.xml` is the package descriptor. Assets under `src/main/resources/static` are published and must not contain secrets. Admin route prefixes can come from the plugin name. Namespace Admin templates and check the URL after export rather than relying on the annotation alone.
- Distinguish three command interfaces: the [SDK](https://youngmonkeys.org/ezyplatform/guides/ezyplatform-sdk-commands?lang=vi) uses `ezy.sh` or `ezy.bat` to scaffold, `link`, sync dependencies, `package`, and `export`; the [runtime CLI](https://youngmonkeys.org/ezyplatform/guides/ezyplatform-cli-commands?lang=vi) manages modules, versions, and servers; and `./scripts/ezy` wraps the pinned CPPAI CLI as documented in the README. Their commands are not interchangeable.
- The development workflow is: select matching SDK and runtime versions → create or import the Maven project → run startup tests for each module → build and export → install and activate → restart if the module requires it. Using `link` on an installed plugin adds its Maven dependency and the package to scan in startup tests. Link only when needed and check versions on both the runtime and the classpath.
- The stack targets EzyPlatform **1.5.9**, **Java 11**, **MySQL 8.0**, and EzyArticle **1.5.6**. Host ports bind to loopback by default; the runtime and database use separate volumes. The Ubuntu and Windows manual installation guides do not replace the pinned Compose workflow. The FAQ requires **Java 8 compatibility for Marketplace releases**; running internally on Java 11 does not establish that.

### Public source code and Javadoc

- [ezyplatform-development @ 7cb8685](https://github.com/youngmonkeys/ezyplatform-development/tree/7cb868578b34d3c834dc9ea290b5b2f61e2b6aa6): Maven parent, SDKs for Admin, Web, HTTP, Socket, and tests, and devtools that generate repositories, pagination, unit tests, and Swagger output. The snapshot uses parent `0.0.2` and is **not** the full 1.5.9 core source. Use it to understand interfaces and patterns, then confirm signatures against Javadoc and the pinned artifact.
- [ezyplatform-examples @ 1ab88a2](https://github.com/youngmonkeys/ezyplatform-examples/tree/1ab88a21a59a6a3e6d00f5277e1996311045c726): `book-store` demonstrates a shared SDK, Admin, Web, and a theme, including pagination, menus, and views. `personal` demonstrates a word-count entity and repository, decorators, event and batch patterns, and startup and integration tests. `vibe-coding-bakery/sweet-bakery` also splits modules and has a Web error handler. Sample SQL is in `personal/personal-admin-plugin/src/main/resources/scripts/`; it establishes script placement and patterns, not guarantees about versions or automatic migration rollback.
- [Java docs 1.5.9](https://ezyplatform.com/java-docs): [Admin](https://ezyplatform.com/versions/1.5.9/java-docs/ezyplatform-admin/allclasses-noframe.html), [Common](https://ezyplatform.com/versions/1.5.9/java-docs/ezyplatform-common/allclasses-noframe.html), [Web](https://ezyplatform.com/versions/1.5.9/java-docs/ezyplatform-web/allclasses-noframe.html), [Socket](https://ezyplatform.com/versions/1.5.9/java-docs/ezyplatform-socket/allclasses-noframe.html). Some guides link to older Javadoc. Verify signatures and package names before copying them.
- Direct references for integration points: [WebAuthenticationInterceptor](https://ezyplatform.com/versions/1.5.9/java-docs/ezyplatform-web/org/youngmonkeys/ezyplatform/web/interceptor/WebAuthenticationInterceptor.html) exposes `getCanBeUseUserIdUris` and `needToCheckPermission`; [WebMediaControllerService](https://ezyplatform.com/versions/1.5.9/java-docs/ezyplatform-web/org/youngmonkeys/ezyplatform/web/controller/service/WebMediaControllerService.html) extends the shared media service; [WebNotificationService](https://ezyplatform.com/versions/1.5.9/java-docs/ezyplatform-web/org/youngmonkeys/ezyplatform/web/service/WebNotificationService.html) exposes `addNotification`; [AdminDataAppender](https://ezyplatform.com/versions/1.5.9/java-docs/ezyplatform-admin/org/youngmonkeys/ezyplatform/admin/appender/AdminDataAppender.html) exposes `doAppend`. The public SDK provides `AdminSearchService.search(adminId, rolesProxy, keyword)`, but its default implementation falls back to an overload with less context. Do not rely on that default to restrict private results.

## Extension points to review before writing a plugin

| Task | Documented extension points | Limits and project decisions |
| --- | --- | --- |
| Admin authentication | `@Authenticated`, `@AdminId`, `@AdminRoles AdminRolesProxy`, `@EzyFeature` | Admin and user identities are distinct. `isAccessible` supports the UI; hiding buttons does not enforce access control. |
| Web authentication | `WebAuthenticationInterceptor`, `@Authenticated`, `@UserId`; for example, override `needToCheckPermission()` | The guide says Web does not require login by default. Test integration with the active theme or login plugin and check every route. Feature permissions do not replace membership checks. |
| Admin UI | Thymeleaf `View`, menus and localization; `ViewDecorator` uses `setVariableIfAbsent` for default variables; `rightToolbarToolFragments` renders the `:: content` fragment. | Avoid database queries whenever the shared menu renders. Use `additionalMessageKeys` to expose keys to JavaScript, and load heavy assets only in views that need them. `previousScreen` preserves navigation; do not accept arbitrary client-supplied redirects. |
| Web UI | Templates, fragments, `ezyweb` helpers, and the global exception and error handler. | Formatting, form error, and localization helpers do not replace server-side validation. An SPA should be a UI layer only; keep API and authorization independent of the theme. |
| Search | `AdminSearchService` returns `SearchResultModel`; global search aggregates results from participating plugins. | Use it for operations only if authorization context can be passed through. Scope Web search in the query itself, including autocomplete and counts. |
| Lists | `Filter → PaginationParameter → Converter → Repository → Service` supports cursor and offset tokens and generates JPQL. Devtools includes a generator. | Consider cursors for frequently changing lists and use a stable tiebreaker. Base64 is not authentication; validate scope, filters, sort order, and page-size limits. `Reactive.multiple()` can batch independent lookups but is not a transaction. |
| Media | `MediaControllerService`, `MediaUpDownloader`, media modal, event hooks, MIME classification, and image resizing. | For private attachments, verify permissions on the parent resource, not just ownership by the uploader. Do not return raw public URLs or use the default modal until listing and downloads are verified to respect scope. Test original files and external adapters. |
| Notifications | `WebNotificationService` and `WebLetterService`, content templates and recipients, plus sample controller services and UI. | Use an adapter after commit. Internal messages are not email, and EzyMail might not be installed. Send only to authorized recipients and deduplicate retries. |
| Internal events | `AdminEventHandlerManager`, `WebEventHandlerManager`, `EventHandler` and `AbstractEventHandler`, priority, and `VoidEvent`. | This is internal dispatch, not a broker or durable queue. An event that returns a result may stop at the first non-null handler response. Keep the durable audit log and outbox in the plugin database. |
| Batch jobs and configuration | `AdminDataAppender` provides batching, checkpoints, and controls to enable, disable, or reload jobs. `SettingService` and `AdminSettingService` read, write, encrypt, and cache settings. | Suitable for backfills or projections if idempotency and single-worker execution are verified. Do not store tenant business data as system settings. Cron supports five or six fields with Sunday as 0, not special Quartz syntax. Account for time zones and DST. |
| Public links | `LinkService.saveLink`, the `ezy_links` table, and an appender keyed by update time. | Use this pattern for published links, not private resource URLs in catalogs or SEO. |
| Low-code | A view schema describes template variables for discovery. `JavascriptService` runs Rhino with exposed beans and object results. | Do not let members enter server-side scripts. Neither extension point is needed for the MVP. |

See the [guide inventory](ezyplatform-guide-inventory.md) for instructions and filenames.

## Operations, data, and publishing

- The [installation guide](https://ezyplatform.com/installation-guide) lists 1 CPU and 2 GB of RAM as minimums, recommends 2 CPUs and 4 GB, and requires Java 8+ and MySQL. Local use does not need a domain; deployments can use separate Admin and Web domains. The [FAQ](https://ezyplatform.com/faq) points to `/modules/add` for installing, activating, and restarting. A public listing does not mean the plugin is available in this stack.
- The [FAQ](https://ezyplatform.com/faq) notes that built-in indexes are defaults; optimize for actual queries. A module release needs multilingual support and package names outside reserved namespaces. Do not bundle files or JARs already in the core, modify existing data without approval, or include assets you cannot redistribute. Follow package size requirements. Commercial use is supported under the [EzyPlatform 1.0.0 license](https://youngmonkeys.org/licenses/ezyplatform-1.0.0.txt); do not infer the core license from the SDK repository license.
- The [migration guide](https://youngmonkeys.org/ezyplatform/guides/migrate-ezyplatform-from-server-a-to-server-b?lang=vi) treats runtime files and database dumps separately. The guide on [multiple instances sharing a database](https://youngmonkeys.org/ezyplatform/guides/install-multiple-ezyplatforms-with-a-single-database?lang=vi) warns about per-instance encryption keys. Multi-tenant applications are not the same as multiple physical installations sharing a database. Back up the runtime, database, and key configuration securely, and verify restoration in a test environment before upgrading.
- The [statistics guide](https://youngmonkeys.org/ezyplatform/guides/ezyplatform-statistics-apis?lang=vi) describes runtime and module lifecycle telemetry and the `allow_send_statistics_data` setting. Evaluate it against deployment policy. Do not use this telemetry in place of plugin business logs or analytics.
- Recovery and troubleshooting guides distinguish JDK errors, missing or mismatched dependencies, working directory issues, failed module installations, and IDE environment problems. Infrastructure guides cover HTTPS reverse proxies, Socket TLS, resources and JVM settings, and logging separately. For this project, avoid direct exposure of Admin and do not copy production installation scripts from examples.

## Scope and confidence

This research covers the text and code examples in public documentation. It does not replace runtime testing, cover entire videos, or verify content that requires sign-in or purchase. Documented APIs and patterns are reported capabilities; integration recommendations are **proposals**. This work did not install or activate plugins, set up an environment, or verify AgentKit.
