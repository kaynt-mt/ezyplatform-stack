# EzyPlatform: using the frameworks in the plugin runtime

Read EzyPlatform's [Overview, Guide, and Samples](https://youngmonkeys.org/projects/ezyplatform?tab=guide&lang=vi) alongside the [76-article inventory](../ezyplatform-guide-inventory.md), [core research](../ezyplatform-deep-research.md), and [runtime plugin smoke-test report](../../plugins/test-report.md). This page connects EzyHTTP, EzyData, Bean, and Socket from the Young Monkeys catalog to Java plugin development rather than repeating those sources.

| Extension | Framework features | Core conventions to preserve |
| --- | --- | --- |
| Web/API and Admin | EzyHTTP binding, interceptors, exceptions, and View. | Route prefixes, `@Authenticated` and identity resolvers, feature permissions and roles for each runtime, `menus.properties`, and views and fragments compatible with the theme. Enforce resource permissions in the domain, not just with `@EzyFeature`. |
| Data | EzyData JPA repositories, projections, queries, and transactions. | Use the runtime data source and the plugin's SQL schema in its Admin module. Verify when migrations run; do not copy automatic schema creation from Boot examples. |
| Wiring | EzyFox Bean scanning, injection, and lifecycle. | Check `module.properties`, dependencies, Maven artifacts and assembly, and the module's scan scope. Do not upgrade individual frameworks just to match newer documentation. |
| Socket | EzyFox Server zones, apps, commands, and the client SDK. | Use EzyPlatform's Socket slot, the correct type of Web or Socket session, and separate activation. Socket is not needed for a CRUD MVP. |

The [plugin quickstart](https://youngmonkeys.org/ezyplatform/guides/ezyplatform-plugin-development-quickstart?lang=vi) and [project structure guide](https://youngmonkeys.org/ezyplatform/guides/the-structure-of-a-plugin-project?lang=vi) use the native SDK. Start with a separate repository and the [plugin creation skill](../../../skills/ezy-build-plugin/SKILL.md), build natively, and install **your own artifact** in Compose dev. The version on a framework page is not the image's SBOM. Check the effective POM, JARs, and annotations, and build with the pinned SDK and runtime.

**Internationalization and security:** The [localization guide](https://youngmonkeys.org/ezyplatform/guides/ezyplatform-multi-languages?lang=vi) covers message bundles, Thymeleaf, and JavaScript. Use `messages.properties` for defaults and `messages_vi.properties` for Vietnamese. Keep business codes stable and do not translate database identifiers. According to the [Web authentication guide](https://youngmonkeys.org/ezyplatform/guides/ezyplatform-web-authentication?lang=vi), Web authentication is not enabled by default. Check the active theme or module's `WebAuthenticationInterceptor`, routes that allow optional identity, and whether feature permissions are enabled. Core [permissions](https://youngmonkeys.org/ezyplatform/guides/permission-in-ezyplatform?lang=vi) do not replace plugin ACLs. [Media Controller Service](https://youngmonkeys.org/ezyplatform/guides/mediacontrollerservice-usage-guide?lang=vi) is a candidate for private attachments, but direct URLs, previews, and revocation remain unverified.

**Events and jobs:** [EventHandlerManager](https://youngmonkeys.org/ezyplatform/guides/create-and-handle-internal-events-in-ezyplatform?lang=vi) describes internal registration and dispatch, not durable delivery after commit. [AdminDataAppender](https://youngmonkeys.org/ezyplatform/guides/guide-to-implementing-batch-jobs-with-admindataappender?lang=vi) shows a scheduled batch query, transform, and save. For notifications or statistics, verify multiple instances and retries separately. Do not replace audit or outbox logic with an unverified hook.

**Implementation order:** scanner and context startup → Admin and Web routes and authentication without data → schema and transaction rollback → API access scoping → private attachments → outbox and notifications → Socket if needed. Do not treat blogs or standalone samples as behavior tested on core 1.5.9.
