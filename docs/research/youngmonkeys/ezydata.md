# EzyData: query scoping, transactions, and projections

Sources: [Overview](https://youngmonkeys.org/projects/ezydata?lang=vi), [How EzyJPA works](https://youngmonkeys.org/ezydata/guides/how-ezyjpa-works?lang=vi), [Query Data](https://youngmonkeys.org/ezydata/guides/ezyjpa-query-data?lang=vi), [Repositories and Transactions](https://youngmonkeys.org/ezydata/guides/guide-to-ezydatabaserepository-ezyjparepository-and-transactions?lang=vi). The MVP uses the runtime's MySQL instance and its own schema. EzyMongo and EzyRedis are separate adapters, not JPA repository requirements.

## Choosing a query

1. Use `@EzyRepository` and `EzyDatabaseRepository` for simple CRUD with adequate scoping, such as an ID and a tenant from the authenticated context. Built-in methods such as `findById` and `deleteByIds` do not enforce ACLs. Bind user values as parameters rather than concatenating query or sort strings.
2. The documentation describes derived queries based on supported prefixes and conditions, **not** sorting inferred from `OrderBy...`. Use `@EzyQuery` to specify conditions, joins, and `order by` explicitly. Make sure every OR branch remains within the access scope predicate. Check binding and indexing conventions against the running artifact instead of assuming Spring Data behavior.
3. `Next` is the final argument and maps to skip/limit, not cursor or keyset pagination. Use a stable sort order with the ID as a tiebreaker. For keyset pagination, implement the after-cursor condition on the sort value and ID, and check scope and filters before using the token. Scope count, search, autocomplete, and export queries as well.
4. [Custom Query Result](https://youngmonkeys.org/ezydata/guides/ezyjpa-custom-query-result?lang=vi) distinguishes JPQL projections, scalars, aggregates, and native query result-class mappings. Return DTOs for list views rather than serializing entities with lazy relationships. Verify aliases, the `COUNT` result type, and empty results on the target MySQL version. Index for actual queries and measure their plans with `EXPLAIN` in development.

## Statement-level transactions are not business transactions

According to the repository guide, generated write queries such as `update...` and `delete...` run in their own transactions; reads do not open a write transaction. **Do not assume** three consecutive repository calls commit together. For a multistep mutation, verify that a single `EzyJpaRepository` method uses one `EntityManager` and one transaction, or use a core transaction API if it is available in the pinned SDK. When managing the transaction manually, begin, write and flush as needed, and commit. Roll back on error and always close the entity manager. Keep external side effects outside the transaction; if a message needs to be sent later, write the outbox entry in the same transaction as the business record. Inject a failure after a partial write to verify that both roll back together.

## Configuration, migrations, and other data stores

- [EzyJPA configuration](https://youngmonkeys.org/ezydata/guides/ezyjpa-configuration?lang=vi) and [multiple data sources](https://youngmonkeys.org/ezydata/guides/ezyjpa-connect-multi-datasources?lang=vi) describe setting up separate factories and contexts and grouping repositories by data source. Plugins use only the context provided by the platform for the core database. Do not create another connection pool or copy automatic schema creation from a framework example into production.
- Keep versioned migration scripts in Admin as described by EzyPlatform. Do not edit released scripts or assume a restart verifies a migration. Test a fresh installation and an upgrade on a copy of the data. A Web smoke test is not enough; see the [notes on missing tables at startup](../../plugins/test-report.md#dependency-order-notes).
- [EzyRedis](https://youngmonkeys.org/ezydata/guides/introduce-ezy-redis?lang=vi) supports caches, counters, and channels. It is not the source of truth for permissions or outbox durability. [EzyMongo](https://youngmonkeys.org/ezydata/guides/introduce-ezymongo?lang=vi) is a document store with its own configuration, queries, and results. Do not add a data store just because an adapter exists.
