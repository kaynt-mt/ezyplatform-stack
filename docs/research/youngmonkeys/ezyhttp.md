# EzyHTTP: controllers, views, and authentication boundaries

Sources: [EzyHTTP Overview](https://youngmonkeys.org/projects/ezyhttp?lang=vi), [handling requests](https://youngmonkeys.org/ezyhttp/guides/ezyhttp-handle-requests?lang=vi), [request arguments](https://youngmonkeys.org/ezyhttp/guides/ezyhttp-request-arguments?lang=vi), and [annotations](https://youngmonkeys.org/ezyhttp/guides/ezyhttp-annotations?lang=vi). The standalone EzyHTTP guides explain the framework. The EzyPlatform runtime already creates the HTTP server, configures views, and registers interceptors. Do not copy the standalone bootstrap, switch from Jetty to Tomcat, or enable CORS just to get a module running.

## From HTTP requests to business logic

| Layer | Framework behavior | Guidance for plugins |
| --- | --- | --- |
| Routing and binding | Controllers map HTTP methods and bind arguments from paths, queries, headers, cookies, bodies, or custom arguments and converters. | Use the path for resource scope, allowlisted query filters, and a DTO with an explicit set of body fields. Do not trust actor or tenant IDs from the request body. |
| Interceptors | `RequestInterceptor` is a singleton. `@Interceptor(priority)` is applied in ascending order. When `preHandle` returns false, the handler does not run; do not rely on `postHandle` to clean up blocked requests. In the standalone guide, an interceptor enforces `@Authenticated`; the annotation does not authenticate by itself. | Verify that EzyPlatform registers the interceptor for the route, and test anonymous and expired sessions. Resolve Web identity with `@UserId` and Admin identity with `@AdminId` in the appropriate adapter. Enforce resource permissions in the service or query. Keep request state out of singletons. |
| Services and controllers | Handlers translate HTTP inputs into service calls. The framework provides default exceptions, controller-specific handling, and shared handlers. | Keep error schemas consistent. Use 400 for invalid input, 401 for unauthenticated requests, 403 or 404 according to disclosure policy, and 409 for stale versions. Do not send stack traces or data source errors to clients. Do not override the core's global handler without assessing the impact. |
| Responses | Ordinary objects are serialized. `ResponseEntity` sets the status or headers; `View` renders a template; `Redirect` starts a new request; `ResponseAsync` hands off the response to asynchronous processing. | Use a DTO or projection for JSON and `View` for UI that needs data. An asynchronous response is not a substitute for a transaction or job. Check the actual route's Content-Type and error body, not just its status. |

Sources for framework behavior: [interceptors](https://youngmonkeys.org/ezyhttp/guides/ezyhttp-request-interceptor?lang=vi), [exceptions](https://youngmonkeys.org/ezyhttp/guides/ezyhttp-handle-exceptions?lang=vi), [response types](https://youngmonkeys.org/ezyhttp/guides/ezyhttp-response-types?lang=vi), and [EzyPlatform Web authentication](https://youngmonkeys.org/ezyplatform/guides/ezyplatform-web-authentication?lang=vi).

## UI, files, and integrations

- [Create a website](https://youngmonkeys.org/ezyhttp/guides/ezyhttp-create-a-website?lang=vi) describes the model → controller → template flow and redirects. Follow the [Admin page conventions](https://youngmonkeys.org/ezyplatform/guides/create-an-admin-page?lang=vi) for core Admin. On Web, verify that the active theme renders the view or fragment. Internationalization uses keys in the plugin's message bundle, not just the HTTP language.
- [Static files](https://youngmonkeys.org/ezyhttp/guides/ezyhttp-serves-static-files?lang=vi) covers locations, URL mappings, asynchronous responses, content types, ranges, and timeouts. Put only public assets under `static/`. [Upload](https://youngmonkeys.org/ezyhttp/guides/ezyhttp-upload-file?lang=vi) and [download](https://youngmonkeys.org/ezyhttp/guides/ezyhttp-download-file?lang=vi) describe synchronous and asynchronous handlers, not application ACLs. For private files, authenticate the caller, check permissions on the parent resource before streaming, and restrict size and content type. Test direct URLs as well.
- The [GraphQL pipeline](https://youngmonkeys.org/ezyhttp/guides/ezyhttp-how-graphql-works?lang=vi) and [fetcher contract](https://youngmonkeys.org/ezyhttp/guides/ezyhttp-graphql-fetcher-implementation-guide?lang=vi) cover dispatch, arguments, response shape, interceptors, and response filtering. Defer GraphQL until REST usage demonstrates the need. If you add GraphQL later, keep authorization in the service so nested resolvers cannot exceed the caller's permissions. Measure query counts and limit page sizes.
- For external APIs, [HttpClient](https://youngmonkeys.org/ezyhttp/guides/guide-to-calling-http-apis-with-httpclient?lang=vi) distinguishes retrieving the body from retrieving the full response. [HttpClientProxy](https://youngmonkeys.org/ezyhttp/guides/guide-to-calling-http-apis-with-httpclientproxy?lang=vi) adds an interface for synchronous and asynchronous calls and downloads. Set timeouts, classify errors, and retry idempotent operations after commit. Do not keep a database transaction open while waiting for SMTP or HTTP.

**Acceptance checks on the pinned artifact:** Confirm route prefixes for Admin and Web; test anonymous, authorized, and unauthorized requests; verify that invalid requests do not write to the database, JS and HTML do not embed tokens, views use the expected language, and direct downloads are blocked after access is revoked. These are planned checks, not test results.
