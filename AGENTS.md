# Working with EzyPlatform Core

- Run `./scripts/up.sh` to start Admin, Web, and MySQL. Run `python3 scripts/sync-upstream.py` to fetch all pinned plugins and skills, including the AgentKit `engineer` and `marketing` kits if `AGENTKIT_API_KEY` is set or you are already logged in to `ak`. The stack's CLI entry points are `./scripts/ezy` and `./scripts/ak`.
- Start with `.agents/skills/ezy-guide/SKILL.md` for EzyPlatform tasks and `.agents/skills/ak-agentkit/SKILL.md` (or `ak-help`) for the AgentKit skills (`ak-*`). Use `ezy-new` and `ezy-sync` for content projects; use `ezy-develop` and `ezyplatform-develop` for themes and plugins. Official skills start with `ezyplatform-`. Their workflows can change, so read `SKILL.md` before running bundled scripts.
- Read the [EzyPlatform blog background and index](docs/research/ezyplatform-blogs/README.md), then open the relevant topic notes and original articles before proposing operations, deployments, or new features. Verify the steps against the skills, Guide, and current stack version.
- Consult the [complete Ezy skill catalog](skills/README.md) and read the checked-in copies in [`skills/upstream/`](skills/upstream/) to choose the right skill for the task. When creating a new Java plugin, follow the [stack's plugin build skill](skills/ezy-build-plugin/SKILL.md) to build natively and verify the artifact in the Docker development environment.
- Keep new applications in separate repositories. Use `ezy new --mode live --admin-url URL` to connect to an existing core or `--mode local` to create an isolated sandbox. Use least privilege, never commit `.env` or `environment.json`, and do not perform writes in production without approval.
- Do not edit generated files under `.upstream/`, `.agents/skills/`, or `skills/upstream/` by hand. Update pins as described in the README and verify Admin and Web in development. Run `python3 scripts/sync-upstream.py --refresh-ezy-skills` to update the checked-in Ezy snapshot.

## AgentKit workflow for bots and Devin sessions

See the [AgentKit workflow](docs/agentkit-workflow.md) for details. Every session must follow these rules:

- **Proportionality gate and hard rules:** Before any multistep task, agree on four items: *Outcome, Constraints, Non-goals, and Acceptance criteria*. Do not fix a bug until you have demonstrated the root cause (`ak-debug` before `ak-fix`; stop and report after three failed attempts). Do not report completion without evidence from an actual run on the final revision, and do not weaken tests.
- **LOCAL / DEV only by default:** Production work, deleting databases or volumes (`docker compose down -v`), editing real `.env` files or secrets, and publishing publicly require separate approval from `chanht_tt`. Allow only one writer per branch or repository at a time. Redact all tokens and secrets from logs, reports, and chat.
- **Choose the applicable skill sequence (AgentKit 3.2.0):**
  - Quick tasks (`trivial`, `low` risk): `ak-scout` (if needed) → `ak-cook --fast --skip-journal` → `ak-test` → `ak-code-review --pending`.
  - Large or multiphase tasks (`epic`): `ak-brainstorm` → `ak-plan --hard` (`validate`/`red-team` for high risk) → split tickets into non-overlapping sets of files through Chief of Staff and Devin Boards → use the EzyPlatform domain skill and `ak-cook` for each phase → `ak-test` → `ak-security` (when touching auth, APIs, databases, or input) → `ak-code-review`.
  - Bug or CI fixes: `ak-scout` → `ak-debug` → `ak-fix` (reproduction test goes from red to green) → `ak-test` → `ak-security` (for security issues) → `ak-code-review --pending`.
  - PR reviews: `ak-review-pr <PR>` (read-only by default; do not use `--fix`, `--reply`, or `--merge` unless assigned) or `ak-code-review --pending`. Add `ak-security` when touching auth, payments, input, or secrets. Classify findings as `Blocker / Should fix / Suggestion` and cite `file:line`.
- **Differences in Devin's `portable` build:** Use `ak-security`, not the old `ak-security-scan` name. Coordinate multiple sessions through **Chief of Staff and Devin Boards**, not `ak-team` or `ak-orchestrate`, which are for Claude Code. Use `ak-worktree` only to isolate branches on a single VM. The `kongming` subagent (`--advice`) is unavailable; use `ak-brainstorm`, `ak-predict`, or `ak-plan red-team` for critical review.
- **Closeout report:** Always include `Status` (`DONE` | `DONE_WITH_CONCERNS` | `BLOCKED`), links to the PR or artifacts, evidence from actual runs, and anything still open or unverified.
